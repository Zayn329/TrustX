# Stage 2 — Proof & Trust Passport: Implementation Report

## Executive Summary
Stage 2 builds upon the Stage 1 vulnerability submission and oracle verification baseline to deliver an end-to-end, verifiable **Proof & Trust Passport** experience. Evaluators and faculty members can trace a vulnerability submission directly into its proof record, perform real-time cryptographic hash integrity verification over the payload, inspect oracle proof signatures, examine researcher identity credentials, and evaluate the deterministic reputation scoring mechanics.

## End-to-End Workflow & Data Flow

```
[ Researcher (did:trust:0x71c89a42e12b) ]
                 │
                 ▼ (Submit Vulnerability)
[ Vulnerability Report ] ──► SHA-256 Payload Hash Generated
                 │
                 ▼ (Oracle Sandbox Execution)
[ Oracle Verification Result ] ──► Ed25519 Cryptographic Signature Produced
                 │
                 ▼ (Explorer & Passport View)
[ Proof Record Inspection Modal ] ──► Real-Time Re-calculation & Integrity Check
                 │
                 ▼ (Trust Engine Consolidation)
[ Trust Score Update (+3 Rep) ] ──► W3C Verifiable Credential Export
```

1. **Submission**: Researcher submits vulnerability report containing title, description, target contract, and PoC calls.
2. **Evidence Hashing**: Web Crypto API hashes the deterministic report payload into `recordedHash`.
3. **Oracle Execution & Signature**: The verifier node (`oracle/server.cjs`) evaluates the PoC calls, issues a status (`valid`/`invalid`), and signs the verification receipt using Ed25519.
4. **Proof Inspection**: The evaluator opens `ProofDetailModal` from either `Contribution Explorer` or `Trust Passport`, clicks "Verify Payload Hash", and confirms live hash match (`Hash Integrity Verified`).
5. **Trust Score Factor**: Valid verified reports increment the researcher's trust score by +3 points, reflected in `ScoreBreakdown` and W3C Verifiable Credentials.

---

## Cryptographic & Verifier Semantics

1. **Evidence Hash Scope**: A deterministic SHA-256 hash computed over `{ id, title, description, reproductionSteps, evidence }`. It guarantees payload immutability and content identification.
2. **Live Re-calculation Utility**: Executes `crypto.subtle.digest('SHA-256')` live in the browser over the current modal report data to demonstrate tamper detection to evaluators.
3. **Oracle Proof Signature**: Ed25519 signature generated by the oracle server (`port 8787`) upon sandbox verification.
4. **Anchoring Status**: Displayed as "Off-Chain Signed & Sepolia Escrow Bound", explicitly clarifying off-chain oracle signatures versus on-chain smart contract transactions.

## Faculty-Facing Step-by-Step Demonstration Walkthrough

1. **Start Services**:
   ```bash
   # Terminal 1: Start Oracle Server
   npm run oracle:server

   # Terminal 2: Start Frontend Application
   npm run dev
   ```
2. **Open Browser**:
   - Navigate to `http://localhost:3000/#passport` in Google Chrome or Mozilla Firefox.
3. **Inspect Researcher Identity & Trust Passport**:
   - Observe researcher profile **Alex Rivera** (`did:trust:0x71c89a42e12b`), verified researcher status badge, and initial Trust Score (97 / 100).
   - Review **Score Breakdown Factors** (+35 Technical Contributions, +30 Bounty History, +20 Verification Rate, +15 Consistency).
4. **Inspect Researcher Submissions & Proof Records**:
   - Scroll to **Verified Submissions & Proof Records** on the Passport view.
   - Click **"Inspect Evidence Hash & Proof"** on `rep-8801`.
5. **Verify Cryptographic Evidence Hash Integrity**:
   - Observe **Recorded Evidence Hash** (`0x08b28dad...`).
   - Click the **"Verify Payload Hash"** button inside the modal.
   - Observe the live recalculated hash generated via Web Crypto API matching the recorded hash with green verification badge: *"Hash Integrity Verified — Payload matches recorded evidence hash exactly"*.
6. **Inspect Oracle Proof Signature & Execution Logs**:
   - Review the **Ed25519 Oracle Signature** and verifier node metadata (*Nexus Security Oracle Worker v1*).
   - Close the inspection modal using **"Close Inspection"**.
7. **Cross-Verify via Contribution Audit Explorer**:
   - Navigate to `#explorer` in the sidebar.
   - Select any contribution and click **"Inspect Proof & Evidence Hash"** to confirm end-to-end data consistency across views.
